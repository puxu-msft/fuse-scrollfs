## 核心问题（这是「全有或全无」的，别只改一半）

热路径必须**同时**改两处，否则引入新数据丢失：
1. **fsync → 追加原始 delta 到 journal（不压缩）**——治写放大。
2. **remount 后未封尾块必须能从 journal 重建**——否则干净卸载重挂后尾块（在 journal）读不出 = **remount 丢已 fsync 数据**（与刚根治的同类 bug）。

只做 (1) 不做 (2) = 引入 remount 丢数据。所以本步覆盖：Store 接口 + ShadowStore 读尾 + wsession journaled_len + container 回退，缺一不可。

## 设计（统一，照此实现）

**Store trait（`store/mod.rs`）新增：**
- `fn supports_tail_journal(&self) -> bool { false }`
- `fn append_tail(&self, ino: Ino, delta: &[u8], new_size: u64) -> io::Result<()>`：持久化未封尾块的原始字节增量。默认 `Err(Unsupported)`；ShadowStore 实现。
- `fn seal_tail_block(&self, ino: Ino, idx: u64, blk: StoredBlock, new_size: u64) -> io::Result<()>`：封块——把累积尾块作为压缩块 idx 落盘并**重置 journal**。默认 = `put_block`（无 journal 的后端）。

**ShadowStore（`store/shadow.rs`）：**
- `supports_tail_journal() = true`。
- `append_tail`：开 `ArchiveUpdater` → `append_journal(delta)` → `commit_journal()`（journal 状态从 SB 跨 open 累积，已支持）。
- `seal_tail_block`：开 updater → `set_block(idx, blk)` → `reset_journal()` → `commit()`。
- `get_block(ino, idx)`：`idx < 封块数` → 既有压缩块；`idx == 封块数` 且有 journal → `read_tail()` 的原始字节包成 `StoredBlock { bytes, stored_verbatim: true }`。
- `block_geometry`：`uncompressed_size` 须含未封尾（来自活跃 SB.uncompressed_size，已含；确认）。

**wsession（`core/wsession.rs`）：**
- `Tail` 加 `journaled_len: usize`（已 journal 的逻辑长度，init 0）。
- fsync 路径（现 `seal`）：若 `store.supports_tail_journal()` → `delta = plain[journaled_len..]`；`store.append_tail(ino, delta, file_size)?`；`journaled_len = plain.len()`。**不压缩**。否则走旧 `store_plain_block`（container 回退）。
- 块满（`append_into_tail` 里 `plain.len()==chunk_size` 的 seal 分支）：`compress(plain)` → `store.seal_tail_block(ino, idx, compressed, file_size)`（重置 journal）；`journaled_len = 0`。
- `ensure_tail_loaded`（remount/无缓冲时）：从 `store.get_block(idx)` 取尾块解压（idx==封块数时返回 journal 尾）；装入后设 `journaled_len = plain.len()`（已全 journal）。

**ContainerStore：** 不支持 journal，`supports_tail_journal()=false`，走旧路径（写放大是 redb/V 的独立议题，不在本步）。

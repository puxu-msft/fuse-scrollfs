## 2. 核心结论（部分推翻先前 zstd-CLI 乐观估计）

### 2.1 块大小是压倒性的、最简单的杠杆——两后端皆然
- Shadow 64KiB→256KiB→1MiB（level 3）：**5.43x → 9.75x → 13.70x**，且**写更快**（1.1s→0.9s，块少压缩调用少）。
- Container 同档：**1.89x → 4.42x → 8.84x**。**64KiB 在 redb 上是病态档**（1.89x！小压缩 blob 撑爆 B-tree 元数据开销），大块直接救活。
- 一句话：**调大块是首选优化**，改一个常量换 2–4x，对 append 负载几乎零代价（尾块缓冲已让 append 成本与块大小解耦；干净写不触发 redb MVCC 膨胀）。

### 2.2 共享字典：真实收益存在但**次于大块**，且不及先前估计
- Shadow 64KiB：off 5.43x → **on 8.22x**（+51%）；level 19：6.13x → **10.24x**（+67%）。Container 64KiB：1.89x → **3.83x**（翻倍）。**字典确实把 boilerplate 长程冗余补回了一部分。**
- **但**：64KiB+字典（Shadow 10.24x / Container 3.83x）**仍输给单纯用 256KiB**（11.20x / 4.42x），更远输 1MiB（15.92x / 8.84x）。
- **修正先前结论**：早前 zstd-CLI 估「64K+512K 字典+L19 ≈ 16x」**偏乐观**——那是单文件 in-sample（字典训练自被压的同一文件 = 过拟合）。真实代码路径 + 多文件泛化下只有 **10.24x**。
- **字典的niche很窄**：仅当被迫保持小块（如 redb 避免大 blob 膨胀的覆盖写场景）才值得；即便如此也要权衡「64K+字典」vs「大块 + 接受 redb 膨胀」。外加字典工程化代价（训练、随容器持久化、版本化、解压每块需常驻）。**结论：保留为 opt-in `--dict`，默认关闭。**

### 2.3 高 zstd 等级（19）不值得
- 比值边际小：64KiB 5.43→6.13（+13%）、1MiB 13.70→15.92（+16%）；**CPU 代价 25–100x**（64KiB/L19 达 103.6s）。
- **小块 + 高等级是病态组合**（64KiB/L19 103.6s vs 1MiB/L19 22.6s）：L19 每次调用固定开销高，小块放大成千上万次。
- **结论：level 3 是甜点；活跃写负载不要默认高等级。** 真要高比值，优先加块大小而非升等级。

## 3. 与先前估计的一致性核对（诚实归因）

| 配置 | 早前 zstd-CLI 估 | 本次真实代码路径 | 差异原因 |
|---|---|---|---|
| 64K/L19 无字典 | 7.0x | 6.13x | archive/启发式开销，-12% |
| 1M/L19 无字典 | 19.4x | 15.92x | 同上 + 每文件边界，-18% |
| 64K/L19 +512K 字典 | 16.0x | 10.24x | **早前单文件 in-sample 过拟合**，真实多文件泛化大幅回落 |

真实代码路径一致地比 CLI 估计低 ~12–18%（archive/per-file 开销），**字典档差异最大**——这是本轮最重要的诚实修正。

## 4. 落到设计与 ROADMAP

1. **T3「algo/chunk 自适应」应优先做「调大块」**：Shadow 建议默认 256KiB–1MiB（无 redb 膨胀，append 友好）；Container 同样受益于大块（干净写下大块反而**减小**容器，与 §6.1 担忧的「覆盖写 MVCC 膨胀」是两回事）。**未擅自改 `DEFAULT_CHUNK_SIZE`**（§6.1 是有记录的决策门 G2 相关），留待 G1 布局取向时连同定夺；当前 `--chunk-size` 已可配。
2. **T3「共享字典压缩」结论 = 已实现 + 已测 + 收益次于大块**：保留 `--dict`/`train-dict` 作研究开关（默认关），不进默认路径。符合「即使收益不稳定也是研究结论，可未来禁用」。
3. **等级**：`--level` 已可配，默认保持 3。

## 5. caveat
- 单语料子集（128MiB，单项目目录）；跨项目/全量可能略移，但相对排名稳健。
- 整文件单次写测**比值**，未测 append 粒度下的吞吐（另见 append-bench）；比值与写粒度无关。
- 物理口径：Shadow 取 archive 树 apparent 字节和；Container 取 redb 文件长度（含预分配/页增长，故 64KiB 档偏大有一部分是 redb 页粒度）。
- 字典物理占用如实计入（+512KiB）；跨更大库摊薄后字典占比可忽略，本子集已包含。
